# 2026-07-22 工作日志

## 简化重做：去掉 Teleport，降低 tabbar z-index（推翻 AppTeleport 方案）
用户认为之前为修 mp 编译报错而新增的 `AppTeleport` 跨端传送门"过于复杂"，要求：不新增组件、不考虑 Teleport，直接去掉所有传送门、弹窗原地渲染，并把流程列表页 tabbar 的 z-index 降低来解决盖住问题。

改动：
- 删除 `src/components/AppTeleport/AppTeleport.vue`（含目录）。
- 5 个文件去掉 `<AppTeleport>`/`</AppTeleport>` 包裹，改为原地渲染：
  - `task/components/popup/WorkflowPopup.vue`：删 import 与开闭标签（overlay 已有 `v-if="visible && showOverlay"`）。
  - `components/system/UserSelector/UserSelector.vue`：把 `v-if="visible"` 从 `<AppTeleport>` 落到 `<view class="user-select-overlay">`。
  - `components/system/DeptSelector/DeptSelector.vue`：同上落到 `dept-select-overlay`。
  - `task/components/WorkflowCategorySelect.vue`：`v-if="showPicker"` 落到 `cat-popup-overlay`。
  - `task/components/WorkflowDefinitionSelect.vue`：`v-if="show"` 落到 `def-sheet`。
  - 上述 5 个文件均删除 `import AppTeleport ...` 行。
- `task/components/WorkflowTabbar.vue`：`.wf-tabbar` 的 `z-index: 100` → `z-index: 1`。
- `src/types/components.d.ts`：手工删除自动生成的 `AppTeleport` 全局组件声明（下次 dev/build 会被插件重生成，已同步清理避免类型悬空引用）。

原理：`WorkflowPopup` 等弹窗与自定义 tabbar 同为 `.page-container`（`position:fixed; overflow:hidden; 无 transform/filter`）的直接子节点，`.page-container` 无 transform 故内部 `position:fixed` 弹窗不被裁剪；弹窗 overlay `z-index:1100` 本就高于 tabbar，原地渲染即可正常盖住；再把 tabbar 降到 `z-index:1` 彻底消除层级干扰。mp 端因不再有 `<Teleport>`，`not supported: Teleport` 编译报错也一并消除。

验证：仅做静态替换（无新增逻辑），`src` 下已无 `AppTeleport` 引用。重型构建 / 类型检查按约定需用户确认，未自动执行（用户此前选择自行验证 mp 编译）。

## 重构：删除冗余 pageType 路由参数，改由 from(tab) 派生 ApprovalType
`ApprovalTabbarType`(waiting/finish/copy/document) 与 `ApprovalType`(approve/myself/readonly) 是 tab→mode 单射。原先列表→详情跳转同时透传 `pageType` 和 `from`，`pageType` 是 `from` 的冗余二次产物。本次落地"只传 from，详情页/操作栏派生 mode"。

改动：
- `task/utils/workflow.ts`：新增 `PAGE_TYPE_BY_TAB: Record<ApprovalTabbarType, ApprovalType> = { waiting:'approve', finish:'readonly', copy:'readonly', document:'myself' }`。
- 4 个列表组件（TaskWaitingList / TaskFinishList / TaskCopyList / MyDocumentList）：`navigate` emit 与 payload 去掉 `pageType` 字段，删 `ApprovalType` import；它们本就知道自己所属 tab。
- `task/index.vue`：`toDetailPage` 去掉 `pageType` 透传，URL 只带 `taskId/businessId/from`；`ApprovalType` import 删除。
- `task/detail.vue`：`from` 改为 `ref<ApprovalTabbarType>`；`onLoad` 由 `q.from` 经 `PAGE_TYPE_BY_TAB` 派生 `pageType`（未知来源回落 readonly，避免误显操作按钮）；`<WorkflowActions>` 去掉 `:type`，只传 `:from`。`pageType` 仍作为内部 ref 供 `showFooter`/`load` 使用。
- `task/components/WorkflowActions.vue`：`type` prop 改为可选；新增 `mode` computed = `props.type ?? (props.from ? PAGE_TYPE_BY_TAB[props.from] : 'readonly')`；模板 `type==='approve'/'myself'` 全部改为 `mode`；`toFlowListPage` 改用 `mode` 兜底。

约定（后续复用）：流程详情相关跳转**只传来源 tab(`from`)**，审批模式一律派生，禁止再新增 `pageType` 路由参数。重型构建/类型检查按约定未自动跑，改动为局部类型重构、已静态核对一致。
