## 任务：彻底修复审批人弹窗不滚动（第三轮，确认真因）
用户第三次反馈审批人列表仍无法滚动。前两轮（height:100% / flex:1+bodyStyle flex）均无效，说明之前根因判断有误。
**真正根因**：`WfPopup` 的 sheet 只设了 `max-height: 70vh`（**非确定高度**）。在 `max-height` 下，子元素的 `height:100%` 与 `flex:1` 百分比高度链无法解析成确定高度 → scroll-view 被内容撑开、没有受限高度 → 永不滚动。对比 `detail.vue` 能滚动，是因为其根 `.page-container` 有**确定 `height: 100vh`**，scroll-view 才能通过 `flex:1; min-height:0` 拿确定高度。`uni-app` H5 的 `scroll-view` 渲染为 `<div class="uni-scroll-view">`，运行时在 `scroll-y` 为 true 时给该 div 加 `overflow-y:auto`（已查运行时确认）；滚动要求该 div 有受限高度。
**彻底修复**：不给 sheet 改死高度（保留自适应），直接给两个 scroll-view（`.wf-approver-body` / `.wf-attach-body`）加 **`max-height: 62vh`**（vh 是确定值，不依赖父级百分比解析）。短列表自适应、长列表滚动。同时移除上一轮误加的 `:body-style="{display:flex,flexDirection:column}"`（干扰项）。
- 注意：不能给 scroll-view 的 class 设 `overflow:hidden`，否则会覆盖 `scroll-y` 注入的 `overflow-y:auto` 导致不滚。
- 潜在同类坑：`TaskVerifyDialog`/`TaskUserOpDialog` 等弹窗的 scroll-view 用 `.wf-popup-scroll { height:100% }` 也依赖 `max-height` sheet，长内容下可能同样不滚；本次仅修 `TaskHistoryPanel`，其余待用户确认是否需要统一。
- 校验：`pnpm lint` 通过；`pnpm type-check` 本项目零错误。
