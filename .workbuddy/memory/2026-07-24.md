## 任务：修复「发起申请弹窗点遮罩后页面跳走」的 bug
- 背景：用户在 start.vue 点「提交申请」→ 弹出统一的 TaskVerifyDialog（mode=pass），点遮罩层后**整个页面被关掉并跳转到流程列表（用户称"首页"）**，属异常。
- 根因（两层）：
  1. `TaskVerifyDialog` 用 `@update:visible="onPopupVisibleChange"` 监听显隐，弹窗内 `submit()` 成功调 `close()` 只 emit `update:visible:false`，但 `onPopupVisibleChange` 见 `false` 就走 `onCancel()` → emit `cancel`。于是**成功提交**和**点遮罩**都触发 `cancel`。
  2. `start.vue` 的 `onStartCancelled` 一收到 `cancel` 就 `uni.redirectTo('/pages-workflow/task/index?tab=document')` 跳走——点遮罩即整页跳转。
- 改动：
  1. `TaskVerifyDialog.vue`：模板 `@update:visible="onPopupVisibleChange"` → `@close="onCancel"`，删除 `onPopupVisibleChange` 函数。改用 `WorkflowPopup` 自带的 `close` 事件代表"用户遮罩/X/取消关闭"，从而与 `submit()` 成功调 `close()`（只 emit update:visible，不 emit close）区分开——**成功不再误发 cancel**。
  2. `start.vue` `onStartCancelled`：删掉 `uni.redirectTo`，仅 `showStartDialog.value = false`（v-model 已同步）。取消弹窗只关弹窗、**停留在发起表单页**（对齐 PC：取消提交审批弹窗不跳转，流程实例已生成可在「我发起」管理）。
- 验证：`pnpm type-check`(vue-tsc --noEmit) EXIT 0。
- 影响面核对：`WorkflowActions.vue` 的 TaskVerifyDialog 仅监听 `@success`、不监听 `@cancel`，本次改动（取消才 emit cancel、成功不再 emit cancel）对它无副作用，无回归。
- 已知遗留（非本次范围）：start.vue 取消后仍停留在表单页，若用户再次点「提交申请」会再调 saveBusiness(addApi) + startWorkFlow 生成新的业务与流程实例（重复），该问题继承自"弹窗前先 startWorkFlow"的既有设计，与本次遮罩跳转 bug 解耦，未动。
